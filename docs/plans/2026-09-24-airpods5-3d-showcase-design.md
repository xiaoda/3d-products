## 一、项目目标与范围

制作一个以 AirPods 5 为主体的交互式产品展示单页，兼顾外观还原、材质质感和操作体验。首版采用“高还原模型 + 摄影棚级灯光 + 可交互展示台”，先做好产品本身，再扩展滚动叙事和特效。

### 已确认约束

1. 主体与几何细节由 Three.js 代码生成，不导入外部 GLB/GLTF 产品模型。
2. 纹理可用于网罩、文字等表面细节，但不能替代主体建模或可交互结构。
3. 目标是展示级高还原，不承诺工业 CAD 精度或微距摄影级复刻。
4. 优先还原耳机非对称曲面、盒体比例、内胆、分件缝隙和铰链结构。
5. 支持桌面与移动端，无需后端、数据库、登录或电商交易功能。

### 首版交付范围

- 充电盒、盒盖、左右耳机及主要外观细节。
- 摄影棚风格材质、环境反射和柔和阴影。
- 旋转、缩放、开合盒盖、耳机取出与归位。
- 预设视角、细节热点、一键重置、当前视角 PNG 导出。
- 响应式页面、基础无障碍支持、性能分级与静态降级。
- 源代码、运行说明、参数说明和测试记录。

### 暂不纳入首版

- 长页面滚动叙事、复杂粒子和泛光特效。
- 真实内部电子结构拆解、实时物理模拟。
- 视频导出、AR 展示、用户账号和管理后台。
- 同时制作全部产品版本。

### 实施前确认与后续待补充

- 具体充电盒版本：用户已确认标准充电盒版，不能混用不同版本的细节。
- 多角度参考图已初步收集，来源与缺失视角见 [参考资料](../reference-manifest.md)；第二阶段继续补充背面、底面参考。
- 用于性能验收的桌面设备和真实手机。

以上事项不改变已确认的“纯 Three.js 程序化建模”路线。

## 二、技术路线与关键决策

### 2.1 建模路线比较

| 路线 | 优点 | 局限 | 决策 |
| --- | --- | --- | --- |
| Three.js 参数化曲面建模 | 尺寸、部件和动画可控，满足纯代码建模要求 | 耳机复杂曲面需要较多精修 | 已选定 |
| 基础球体、圆柱体组合 | 开发快，适合验证比例和交互 | 容易产生拼接感，不适合作为最终高还原模型 | 仅用于早期白模 |
| 外部精细模型 + Three.js 渲染 | 更适合商业级近景展示 | 不符合本项目已确认的建模要求 | 不采用 |

### 2.2 推荐技术栈

| 技术 | 用途 |
| --- | --- |
| Vite | 本地开发、模块组织与生产构建 |
| TypeScript | 模型参数、交互状态和模块接口的类型管理 |
| Three.js | 程序化几何、材质、灯光、渲染与拾取 |
| 原生 HTML/CSS | 页面布局、操作按钮、热点说明和响应式适配 |
| 统一动画控制器 | 管理盒盖、耳机和相机过渡，避免动画冲突 |
| Vitest | 几何参数与交互状态的单元测试 |
| 浏览器测试 / Playwright | 交互回归、尺寸适配和错误状态验证 |
| Chrome DevTools MCP | 本地页面快照、视觉截图和运行状态检查 |

实施时验证依赖兼容性并锁定版本，不在方案阶段猜测版本号。

### 2.3 决策记录

**决策一：采用参数化几何，而不是外部产品模型。**

- 原因：满足用户明确要求，同时方便修改尺寸、控制零件和复用建模逻辑。
- 代价：曲面连续性和细节还原需要投入更多开发时间。
- 控制措施：先完成白模外形验收，避免在错误轮廓上继续制作材质和动画。

**决策二：首版使用轻量单页架构。**

- 原因：产品展示无需后端，界面复杂度也不需要完整应用框架。
- 代价：后续若扩展大量页面或内容管理，需要重新评估前端框架。
- 控制措施：保持模型、场景、交互和界面独立，避免与 DOM 紧耦合。

**决策三：以确定性的预设动画代替物理模拟。**

- 原因：开盖和耳机取出需要可控、流畅、无穿模，不需要真实动力学。
- 代价：不支持任意拖动物体后的真实碰撞。
- 控制措施：明确交互边界，集中管理状态与动画过渡。

## 三、3D 建模设计

### 3.1 尺寸与参考依据

按 Apple 官方规格建立整体比例：

- 单只耳机：高 30.2 × 宽 18.3 × 深 18.1 mm。
- 充电盒：高 46.2 × 宽 50.1 × 深 21.2 mm。

来源：[Apple AirPods 5 官方规格](https://www.apple.com/airpods-5/specs/)。

这些尺寸用于约束整体包围尺寸，不足以确定完整曲面；具体轮廓、开口和细节位置仍需结合多角度参考图校准。公开资料没有给出的内部结构，不应宣称为真实还原。

统一以毫米保存建模参数，再转换成统一的场景单位。将产品版本、尺寸、曲面控制参数与展示参数放入配置文件。

### 3.2 模型层级

```text
ProductRoot
├── CaseBody          盒体外壳
├── CaseInterior      内胆与耳机槽
├── LidPivot          铰链位置的旋转节点
│   └── CaseLid       盒盖及内侧结构
├── LeftEarbud        左耳机
├── RightEarbud       右耳机
└── Details           指示灯、接口、金属件等
```

细节节点应归属于实际运动的部件；上图的 `Details` 是逻辑分类，不要求所有细节都挂在同一父节点。

关键原则：

- 盒盖绕铰链转动，不绕自身中心旋转。
- 耳机使用独立局部坐标和姿态参数，便于取出、归位和单体特写。
- 左右耳机可复用基础生成逻辑，但不能假设所有细节都完全镜像。
- 分离产品自身的坐标与展示姿态，避免相机变化污染模型参数。

### 3.3 各部件建模方法

| 部件 | 实现方式 |
| --- | --- |
| 盒体、盒盖 | 从圆角盒白模开始，再用参数化截面生成最终轮廓 |
| 耳机头部 | 使用多组非对称截面构造连续曲面，避免直接拼接球体 |
| 耳机柄 | 沿路径扫掠变化截面，与头部过渡区域衔接 |
| 内胆、收纳槽 | 分别构造开口、槽壁与底面，不用黑色平面冒充真实深度 |
| 网罩、微孔 | 凹槽几何结合纹理，避免为每个微孔创建复杂网格 |
| 传感器、金属触点 | 独立小网格和材质，方便调整位置 |
| 分件缝隙、接口 | 以真实深度和边缘结构处理影响轮廓或近景的部分 |

最终曲面主要通过 `BufferGeometry` 控制顶点、索引、法线和 UV。`RoundedBoxGeometry` 用于规则圆角部件和初期白模。

技术参考：

- [Three.js BufferGeometry](https://threejs.org/docs/pages/BufferGeometry.html)
- [Three.js RoundedBoxGeometry](https://threejs.org/docs/pages/RoundedBoxGeometry.html)

### 3.4 建模验收顺序

1. 整体轮廓。
2. 部件比例与位置。
3. 曲面连续性和高光过渡。
4. 开口、内胆与分件细节。
5. 材质与细微表面效果。

不得用强高光、过曝或过远镜头掩盖造型问题。

## 四、视觉与页面设计

### 4.1 视觉方向

采用浅灰摄影棚背景、白色产品、大留白与少量深色文字。重点呈现柔和高光、外壳曲面、分件缝隙和悬浮阴影，不堆砌粒子、霓虹光或强泛光。

### 4.2 页面布局

- 顶部：产品名称与简短说明。
- 中心：占主要空间的 3D 展示台。
- 底部工具栏：开合、取出/归位、视角、重置和图片导出。
- 侧边说明卡：点击热点后出现；移动端调整到模型下方。
- 状态区：展示加载、重试、降级和操作反馈。

### 4.3 基础设计约定

- 间距采用 `8 / 16 / 24 / 32 / 48`。
- 正文以 `16px` 起步，标题按视口响应式缩放。
- 字体优先本机系统无衬线，中文使用苹方或微软雅黑等回退。
- 按钮区分默认、悬停、焦点、选中、加载和禁用状态。
- 提供可见焦点、合理触控区域与可读文字对比度。
- 重要说明使用 HTML 文本，不只绘制在 Canvas 内。

### 4.4 材质与灯光

- 白色外壳：非金属 PBR 材质，保留合理粗糙度，避免镜面陶瓷感。
- 金属部件：独立控制金属度、粗糙度和反射强度。
- 网罩与传感器：深色材质保留层次，避免全部压成纯黑。
- 环境反射：使用摄影棚式环境塑造长条高光。
- 阴影：柔和接触阴影，保持产品与背景之间的空间关系。
- 色彩与曝光：统一设置，避免白色外壳因过曝丢失轮廓。

外壳优先评估 `MeshPhysicalMaterial`，只开启确有必要的特性。该材质像素开销较高，官方建议配合环境贴图使用。

参考：[Three.js MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)。

## 五、交互设计

### 5.1 首版功能

| 功能 | 预期行为 |
| --- | --- |
| 旋转与缩放 | 鼠标拖拽、触摸旋转，限制距离和角度，防止进入模型内部 |
| 盒盖开合 | 通过按钮或点击盒盖触发，绕铰链平滑旋转 |
| 耳机取出 | 先开盖，再沿预设轨迹升起并分开 |
| 耳机归位 | 先返回收纳槽，再允许关盖 |
| 预设视角 | 正面、背面、顶部和耳机特写 |
| 热点说明 | 查看接口、传感器等细节；被模型遮挡时隐藏 |
| 一键重置 | 恢复相机、零件姿态和界面状态 |
| 导出展示图 | 导出当前视角的纯产品场景 PNG，首版目标为 2048px 长边，不包含 HTML 工具栏 |

旋转、缩放基于 `OrbitControls`，加入产品展示所需的距离与角度约束。

参考：[Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)。

### 5.2 产品状态转换

```text
闭合 → 开盖中 → 已开盖 → 取出中 → 展示中
展示中 → 归位中 → 已开盖 → 关盖中 → 闭合
```

动画实现要求：

- 连续点击不能叠加冲突动画，统一决定忽略、排队或切换到新目标。
- 相机过渡期间暂停手动相机控制，结束后恢复。
- 通过位移阈值区分点击与拖动，防止旋转结束误触开盖。
- 耳机未归位时不能直接关盖造成穿模。
- 重置操作应能可靠中止当前动画并恢复完整状态。
- 动画由统一时间源驱动，避免多个独立循环争抢同一属性。

### 5.3 移动端与无障碍

- 区分 3D 操作区域与页面滚动区域，不锁死整页滚动。
- 核心操作提供键盘可触达的 HTML 按钮。
- 提供明确的按钮名称、操作反馈与可见焦点。
- 尊重“减少动态效果”设置，关闭自动旋转等非必要动画。
- 热点说明除空间标记外，也可通过界面入口访问。

### 6.2 数据流

```text
产品配置 → 几何生成 → 产品节点 → 场景渲染

用户操作 → 交互控制器 → 更新部件与相机 → 渲染
                      └→ 同步按钮和说明状态
```

职责边界：

- 模型模块负责几何和部件接口，不直接操作页面 DOM。
- 场景模块负责渲染器、相机、灯光和画质。
- 交互控制器集中管理状态、拾取和动画目标。
- 界面模块发送用户意图并订阅展示状态，不直接修改零件坐标。
- 导出模块临时调整输出分辨率，导出完成后恢复原有渲染状态。

### 6.3 生命周期

- 几何只在初始化或建模参数改变时生成，不在每帧重建。
- 复用材质和可共享几何，避免无意义的对象分配。
- 页面不可见时暂停非必要动画。
- 卸载或销毁时释放几何、材质、纹理、渲染目标和事件监听。

## 七、性能、异常与安全边界

### 7.1 性能目标

- 桌面交互目标接近 60 FPS。
- 约定的中端真实手机目标不低于 30 FPS。
- 以上为目标，不是未经过实测的承诺；验收须记录设备、分辨率、浏览器和画质档位。

优化顺序：

1. 限制高分屏渲染像素比。
2. 减少不必要的材质特性、阴影开销和后处理。
3. 控制曲面细分、微小几何与绘制调用数量。
4. 依据实测建立高、低画质配置。
5. 场景静止且无动画、无控制器阻尼变化时，评估按需渲染。

### 7.2 状态与降级

| 状态 | 处理方式 |
| --- | --- |
| 加载中 | 展示静态预览与真实加载状态，不制造虚假进度 |
| 素材缺失或加载失败 | 提示具体问题，提供重试或简化材质 |
| 环境反射不可用 | 使用基础灯光与替代环境，保证产品仍可见 |
| WebGL 不可用 | 展示静态产品图和文本说明 |
| 图形上下文丢失 | 提示恢复或重试，失败则退回静态展示 |
| 图片导出失败 | 显示错误信息并恢复正常渲染，不影响后续交互 |
| 缺少热点内容 | 隐藏无内容入口，避免空白说明卡 |

### 7.3 素材和运行边界

- 记录第三方纹理、环境资源与参考素材的来源及使用许可。
- 不默认复制并发布官方页面素材；参考用途与发布用途分开管理。
- 运行时不依赖不受控的外链素材，优先使用项目内静态资源。
- 保持图片与纹理同源或正确配置跨域访问，避免导出受到跨域限制。
- 项目不接入真实设备、不收集用户个人信息，也不模拟官方购买流程。
- 展示中的产品能力描述应与选定版本一致，不暗示网页实现了真实降噪等硬件能力。

## 八、开发阶段与里程碑

采用六个顺序开发阶段，每阶段都有本地可运行页面、验收步骤、证据与明确的通过标准。具体范围、文件和验收清单见：[分阶段实施与验收计划](./2026-09-24-airpods5-phased-delivery-plan.md)。

| 阶段 | 可验收成果 | 重点验收 | 预计工作量 |
| --- | --- | --- | --- |
| 1. 工程与基础白模 | 可旋转、缩放的充电盒和左右耳机白模页面 | 页面能运行，部件齐全，基础比例与坐标正确 | 1 天 |
| 2. 高还原几何模型 | 可多角度查看的精修灰模，含内胆、铰链和主要细节 | 多视图轮廓、曲面连续性、开盖结构和装配关系 | 3–5 天 |
| 3. 材质与灯光 | 可旋转的摄影棚风格产品展示，附固定视角截图 | 白色塑料、金属、网罩、高光和阴影质感 | 1–2 天 |
| 4. 核心交互 | 开合、取出、归位、预设视角和重置的完整操作演示 | 动画闭环、无明显穿模、快速操作和中途重置可靠 | 1–2 天 |
| 5. 完整页面与图片导出 | 桌面/移动端页面、热点说明和 2048px 长边 PNG 导出 | 布局、触摸、键盘操作、热点遮挡和实际导出文件 | 1–2 天 |
| 6. 优化与最终交付 | 可构建的生产版本、测试报告、运行文档和交付清单 | 性能、兼容、异常降级、资源释放和完整回归 | 1–2 天 |

**展示级首版预计合计 8–14 个工作日。** 估算基于一名熟悉 Three.js 的开发者、参考资料齐全和单一产品版本，不含等待验收时间及新增需求，不是固定交付承诺。

### 阶段推进规则

1. 每阶段完成后先自测，再提交本地预览入口、截图和验收记录。
2. 阶段一验收基础比例；阶段二单独验收最终几何形体，避免把粗白模当成最终外形。
3. 阶段二几何形体未经用户确认，不进入正式材质精修。
4. 用户提出的阶段范围内问题修复后重新验收，通过后再进入下一阶段。
5. 编译成功、自动化测试通过和人工视觉验收分别记录，不能相互替代。
6. 新增需求单独记录，说明对当前范围与工作量的影响，不默认混入后续阶段。

**开发顺序：基础白模 → 精修灰模 → 材质灯光 → 核心交互 → 完整页面与导出 → 优化交付。**

## 九、测试与最终验收

### 9.1 模型和状态测试

- 检查几何顶点无 `NaN`、索引不越界、法线有效。
- 检查主要部件包围尺寸与配置一致。
- 检查开合、取出、归位状态转换与非法操作处理。
- 检查连续快速点击、一键重置和动画中断后的最终状态。
- 检查图片导出结束后相机比例与渲染尺寸正确恢复。

### 9.2 视觉验收

- 从固定正面、侧面、背面和顶部视角与参考图对比。
- 确认轮廓、主要细节位置、曲面高光和分件缝隙合理。
- 确认盒盖开合和耳机运动时无明显穿模。
- 确认不同页面尺寸下模型不被裁切，工具栏不遮挡关键区域。
- 确认热点遮挡关系和说明卡位置合理。
- 在约定参考环境保留截图基线；不同 GPU 的细微像素差异不直接视为造型错误。

### 9.3 兼容与异常验收

- 在 Chrome、Edge、Safari 及至少一台真实手机上验证；如当前环境缺少某设备，明确记录未验证项，不以模拟器替代全部真机测试。
- 验证移动端触摸与页面滚动不存在严重冲突。
- 验证加载失败、素材缺失、WebGL 不可用等降级路径。
- 验证键盘导航、焦点显示和减少动态效果设置。
- 验证页面销毁后资源释放，重复进入不会持续泄漏图形资源。

### 9.4 本地浏览器验证约定

1. 优先使用已配置的 `chrome-devtools`，先发现工具并调用 `list_pages`。
2. 创建本任务拥有的页面，并使用唯一 `isolatedContext`；所有操作传入本次返回的 `pageId`。
3. 通过仅监听 `127.0.0.1` 的本地 HTTP 开发服务预览，不默认使用 `file://`，不监听 `0.0.0.0`。
4. 确认启动后的实际端口与加载结果，不沿用旧会话端口。
5. 使用页面快照检查结构，用实际截图检查视觉；截图只返回路径时读取图片后再判断。
6. 不把“编译成功”“浏览器连接成功”或“无头模式无窗口”混同为页面已成功渲染或无法使用浏览器。
7. 只清理本任务创建的页面与测试进程，不关闭其他任务浏览器。

## 十、主要风险与应对

| 风险 | 应对方式 |
| --- | --- |
| 耳机有机曲面精修成本高 | 先白模、多视图对照，建立参数化截面，不用基础几何拼接作为最终造型 |
| 产品版本或参考图不一致 | 建模前固定版本与参考集合，所有细节按同一版本核对 |
| 白色外壳缺乏层次或过曝 | 优先调整环境反射、粗糙度和曝光，而非直接增加特效 |
| 高频操作引发动画冲突 | 集中管理状态和时间源，测试连续点击与重置 |
| 移动端发热或掉帧 | 限制像素比、降低阴影和材质复杂度，真实设备实测 |
| 近景细节超出既定精度 | 明确展示级边界，额外微距需求单独评估 |
| 首版范围不断扩大 | 先完成核心展示闭环，滚动叙事和内部拆解延后 |
